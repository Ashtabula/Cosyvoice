# CosyVoice3 iOS SDK publication tree

Status: Development. Publication target: `Ashtabula/Cosyvoice/ios/`.

Development source of truth remains `Ashtabula/CosyVoice3_NPU@878940245562bcd1dd0231d78157ba78d70b39f6`. The Swift package now contains a real application-facing `CosyVoice3Engine` and an extracted fixed225 on-device path: native tokenizer/prefill -> stateful Core ML LLM -> Swift RAS -> Flow -> FP64-F0/HiFT -> mono Float32 PCM at 24 kHz. Benchmark/UI/runner code is not a runtime dependency.

The currently wired production-development profile is intentionally narrow: at most 225 generated speech tokens feeding a 225-token / 450-frame / 9-second acoustic bucket. Upstream stop-token handling is preserved; upstream max-length exhaustion is a normal completion, not an error, and this publication lane caps the upstream 20x text-token maximum at the 225-token downstream bucket capacity. An early upstream stop can therefore still produce fewer than 225 tokens and remains outside the current fixed acoustic bucket. The existing baked-reference Flow-conditioning asset remains supported for the default-reference lane.

Custom reference code is also implemented, but it is separately release-gated. The fixed225 custom-reference profile consumes the first 6.056 seconds of a reference and produces the exact fixed tensors required by the current Flow bucket: Whisper128 [1,128,605] -> 151 speech tokens, Kaldi80 [1,604,80] -> CAMPPlus [1,192], and Matcha prompt mel [1,302,80]. Flow conditioning is dynamic per request rather than baked into the model. `CosyVoice3Engine` reports custom-reference support only when `referenceEnrollment.status == "PASS_DEVICE_PARITY"` in the runtime asset manifest.

Python remains conversion/validation tooling only. The shipping runtime path uses Swift, AVFoundation, Accelerate, Core ML and swift-transformers. Candidate reference assets are generated by `tools/export_reference_frontend_tables.py`, `tools/convert_reference_onnx_to_coreml.py`, and `tools/export_dynamic_flow_conditions.py`; they are not promoted merely because conversion succeeds.

The package CI command `swift test --package-path ios` passed at publication commit `44da9c1144e78273ea1e635b3641afdf73bf5904` in GitHub Actions run 37007257072. This is source/build evidence, not physical-iPhone audio/parity evidence.

This is still not a Candidate SDK. Remaining gates include immutable asset distribution/fetch, one-command pinned rebuild, custom-reference numerical + physical-device parity, public-API iPhone text/reference-to-PCM smoke, cold/warm benchmark receipts, clean-room integration, human audio review for Production, and redistribution-license review.

Exact token semantics remain: speech 0...6560, SOS 6561, actual EOS 6562, task 6563, fill 6564, stop IDs 6561...6760. Requesting `.cpuAndNeuralEngine` is not evidence of ANE residency; accelerator residency remains unclaimed.
